This is a **hypothetical BPMN change**, not an implemented Simple-ERP feature
or accuracy ground truth. It uses a validated Staff L3 diagram as the old input
and does not modify Simple-ERP. The BPMN is a process blueprint, not a runtime
file read by the ERP.

The add-document diagram adds Staff `userTask`
`role_staff_l3_pr_create_attachment` before the existing PR input task. The
requirement is one mandatory PDF (maximum 1 MiB) persisted with the new draft
PR; absence/invalidity must leave no new draft. Existing BPMN element IDs,
types, names, and other flows remain stable. Expected graph diff: one
`ADD_TASK` and two `MODIFY_SEQUENCE_FLOW` records (one rewired, one added). The
flow records are consequences of the insertion, not independent requirements
to change two code files.

The gateway and sequence-label files are generated by the hash-locked
`gateway-condition.json` and `sequence-flow-label.json` specs. Both retain the
original BPMN-DI positions. An explicit branch-condition edit emits both
`MODIFY_SEQUENCE_FLOW` and `MODIFY_GATEWAY_CONDITION`; these are related
reports of one BPMN edit, not two independently proven code impacts. A branch
label edit with an unchanged explicit condition emits only
`MODIFY_SEQUENCE_FLOW`. A gateway *label* change is deliberately not mixed
into the gateway-condition scenario.

For a local run, choose `C:\Simple-ERP` as the repository, the old/new BPMN
paths above, and BM25 or the production Hybrid method. In the CLI, use:

```powershell
$env:GOCACHE='C:\BPMN-Impact-Mapper\.gocache'
go run .\cmd\bpmn-impact-mapper analyze --repo C:\Simple-ERP --old-bpmn C:\Simple-ERP\docs\bpm-haqi\roles\staff\p2p\level-3\role-staff-l3-pr-create.bpmn --new-bpmn experiments\simple-erp\staff-p2p\role-staff-l3-pr-create-add-document.bpmn --output outputs\staff-p2p-add-document --repository-name Simple-ERP --revision c934497-dirty --method hybrid --top-k 10 --ignore 'scripts/bpm-haqi/**' --ignore 'docs/bpm-haqi/**' --ignore 'docs/bpmn/**'
```

The ignore rules explicitly exclude case-study BPMN source, generated previews, and BPMN
generation tooling from **retrieval**. They are scenario configuration, not a
Simple-ERP rule embedded in the mapper. Without these filters, the first BM25
probe ranked BPMN generator/preview artifacts above implementation files.
Even after filtering, the BM25-only top results were not a convincing
implementation map. That observation is diagnostic, not an accuracy metric.
Default ingestion now also excludes `.generated` directories and BPMN
specification/tooling trees directly under `docs` or `scripts`. This applies
to both CLI and web; restart the backend for the web to use the updated rules.
The explicit ignore flags remain in the command to record the experiment
corpus policy. No ranking accuracy improvement has been established yet.

Before formal evaluation, freeze the source working tree and both BPMN hashes,
then build independent implementation-based or blind-reviewed file labels.
Do not derive ground truth from mapper rankings or this README.
